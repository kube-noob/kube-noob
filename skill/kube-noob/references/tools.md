# kube-noob tools

Generated by scripts/build_skill.py from the bundled server code; run any of them with
`python3 -I scripts/kn.py TOOL '<json arguments>'`. Arguments marked * are required.

## api_history

API removal history and version map. Removed/deprecated Kubernetes APIs relevant to a target version, and the OpenShift->Kubernetes version map.

- `kind` (null/string)
- `platform` (string)
- `version` (null/string)

## audit_manifests

Audit manifests. Full deterministic audit: security, network exposure, storage access modes, reliability and red-team scenarios. Findings carry rule ids, line numbers, fixes, citations and matching RHACS policy names. On a large manifest set pass compact=true: the same report, with each rule's constants hoisted once into ruleInfo instead of repeated on every finding, which is lossless and about a third smaller.

- `cni` (null/string): The cluster's CNI as NAME or NAME:VERSION (calico:3.32, ovn-kubernetes, cilium:1.18). No manifest states it, so KN-N014 -- an AdminNetworkPolicy or BaselineAdminNetworkPolicy the CNI stopped enforcing, which Calico did in 3.32 without reporting an error -- is NOT EVALUATED unless you name it, rather than counted clean.
- `compact` (boolean): Return the same report with each rule's constant fields (title, severity, stage, category, remediation, citations, stackroxPolicies, controls) collected once into a `ruleInfo` map keyed by rule id instead of repeated on every finding. Lossless and about a third smaller on a report where rules fire more than once; the findings keep their order, rule id, resource, line and message. Off by default so the flat shape stays what it was.
- `exceptions` (null/string): An exception list (YAML, apiVersion kube-noob.io/v1, kind ExceptionList): each entry names a rule, a scope, an owner, a reason and an expiry date. Active entries hide the findings they cover; expired and refused entries are reported and fail the gate.
- `manifests`* (string): One or more YAML documents (Kubernetes/OpenShift objects).
- `min_severity` (string): Hide findings below this severity.
- `partial_bundle` (boolean): Set when these documents are only part of a namespace (one file, a diff, staged changes). Rules that fire because another object is absent -- no NetworkPolicy selects this workload, no PodDisruptionBudget, a StorageClass not declared here -- are then not evaluated, because from a partial bundle they cannot tell a real gap from an object you did not pass. The report says so in its assumptions.
- `platform` (string): Target platform.
- `stages` (array)
- `version` (null/string): Platform version, e.g. '4.22' (OCP) or '1.35'.

## build_diagnose

Diagnose a failed build log. Read a failed GitHub Actions, Jenkins, Tekton or OpenShift build log: the failing step (and why it is that step), the error line and its template, the cause class (dependency fetch, compile, test, image push, registry auth, quota, timeout, out of memory, permissions) with its evidence, reported issues, team memory and the fix for that CI system. Read-only.

- `log`* (string): A failed build or pipeline log: GitHub Actions, Jenkins, Tekton (tkn ... logs) or an OpenShift build (oc logs build/<name>). The end of the log matters most: when cutting, keep the end.
- `platform` (null/string)
- `version` (null/string): The cluster's OpenShift version, for reported issues that may apply.

## check_network_policy

Would this traffic be allowed?. Evaluate NetworkPolicies offline: can the source reach the destination on this port? Checks egress from the source and ingress to the destination, names the policy and rule that decide each, says why the other rules did not match, and proposes the smallest NetworkPolicy that would allow it.

- `cni` (null/string): The cluster's CNI as NAME or NAME:VERSION (calico:3.32, ovn-kubernetes, cilium:1.18). Given, it decides whether AdminNetworkPolicy and BaselineAdminNetworkPolicy are enforced at all: Calico ignores both from 3.32 onward, so policies in that tier are reported as inert instead of deciding the answer, and a CNI whose enforcement is undocumented makes the verdict undetermined rather than guessing either way.
- `default_namespace` (string): For objects without one.
- `destination`* (string): Where it goes: namespace/name of a workload (namespace/kind/name when names clash), namespace:key=value,... for a set of pod labels, or an IP address / CIDR outside the cluster.
- `manifests`* (string): The NetworkPolicies and the workloads they apply to (Deployments, Pods ...); add Namespace objects when policies select namespaces by label.
- `platform` (null/string)
- `port`* (integer/string): Destination port number (1-65535) or a named container port.
- `protocol` (string)
- `source`* (string): Where the connection starts: namespace/name of a workload (namespace/kind/name when names clash), namespace:key=value,... for a set of pod labels, or an IP address / CIDR outside the cluster.

## diagnose

Diagnose symptoms offline. Match pasted events / describe output / logs / CLI errors or an Alertmanager webhook payload against troubleshooting playbooks, ranked by matching patterns and by the signals the text carries (alert names, reasons); returns the signals, ranked root causes, read-only checks with names filled in, fixes, reported issues for the version and policy denials.

- `limit` (integer)
- `platform` (null/string)
- `text`* (string): Events, `describe` output, logs, CLI errors, status JSON, Ceph health output (`ceph health detail`, `ceph status`, their JSON or a CephCluster) or an Alertmanager webhook payload (its alerts are read as text; an `openshift_version` or `version` label gives the version).
- `version` (null/string): The cluster's OpenShift version (4.20 or 4.20.8): leaves out reported issues already fixed there.

## explain_denial

Why was this denied?. Explain an admission denial policy by policy: Kyverno, OPA Gatekeeper, ValidatingAdmissionPolicy, Pod Security Admission, OpenShift SCC, RHACS, ResourceQuota, LimitRange or RBAC. Returns the policy and rule, the failing field, read-only commands with names filled in, the fix (with a patch for Pod Security and RBAC) and the audit rules that catch it before deploy.

- `platform` (null/string)
- `text`* (string): The denial as printed: `kubectl apply` or `oc apply` output, a FailedCreate event or a Warning.

## explain_rule

Explain an audit rule. Rationale, remediation, citations for a rule id.

- `rule_id`* (string): e.g. KN-S001

## extract_signals

Extract signals. Read the canonical names in an error: Alertmanager alert names (webhook payload or text), event and ClusterOperator condition reasons, container reasons, admission rules, components and normalised error templates, plus the alerts its words imply. Returns each signal with where it was found, the catalogue entry (components, playbooks, upstream source) and the playbooks it points at. Read-only and offline.

- `text`* (string): An Alertmanager payload, events, a ClusterOperator, pod status, logs or an error in words.

## fedramp_ksi

FedRAMP 20x KSI evidence. Which FedRAMP 20x Key Security Indicators an audit's findings are evidence for, by inverting the NIST control list each indicator carries in FedRAMP's own consolidated dataset (vendored with its version and hash). Without manifests it returns the crosswalk itself. Every indicator is listed: the ones no kube-noob rule can see carry evidenced=false and no counts, and two carry a warning because their rules reach them only through a shared control and not a shared subject. A mapping is evidence, never a claim of compliance -- an assessment decides whether an indicator is met.

- `cni` (null/string): The cluster's CNI as NAME or NAME:VERSION (calico:3.32, ovn-kubernetes, cilium:1.18). Without it the rule that decides whether an AdminNetworkPolicy is inert cannot decide, and the row says so instead of counting it clean.
- `control` (null/string): Only the indicators citing this NIST control, in kube-noob's spelling: 'AC-6', 'AC-6(10)'.
- `evidenced_only` (boolean): Hide the indicators no kube-noob rule can evidence. The reply says how many were hidden.
- `exceptions` (null/string): The same exception list `audit_manifests` takes (YAML, apiVersion kube-noob.io/v1, kind ExceptionList). Active entries move their findings from `findings` to `excepted` on the indicators they reach, so a KSI page reconciles with the audit instead of counting a signed-off finding as open.
- `indicator` (null/string): One indicator by id, e.g. 'KSI-IAM-ELP'. Ids are mnemonics, not numbers.
- `manifests` (null/string): One or more YAML documents to audit first. Omit to get the crosswalk with no findings.
- `min_severity` (string): Hide findings below this severity. The default is `audit_manifests`' default, because this view is a projection of one audit: a rule whose finding this threshold removed is reported as `withheld` on its indicators rather than counted clean.
- `partial_bundle` (boolean): These documents are only part of a namespace. Default true here, unlike audit_manifests: a pasted manifest is usually a fragment, and a rule that fires because another object is absent cannot tell a real gap from an object the caller did not paste. Set false only for a whole namespace. This is the one input whose default differs between the two views (N14, G246): the threshold and the exception list are now shared, and this one stays because a pasted fragment and a directory are not the same input -- pass the same value to both tools and they report the same numbers.
- `platform` (null/string): Target platform. Unset means the server's configured defaultPlatform, which is what the `ksi` command uses -- a fixed default here made the two front doors disagree on a configured server.
- `version` (null/string): Platform version, e.g. '4.22' (OCP) or '1.35'.

## fix_manifests

Apply safe mechanical fixes. Migrates removed APIs, fixes wrong API groups, hardens securityContext, adds Route TLS, unblocks PDBs, reorders EgressFirewall rules, swaps RWO-only classes for RWX claims. Returns the diff log and manual follow-ups. Does not touch any cluster.

- `harden` (boolean): Apply securityContext hardening (restricted profile).
- `manifests`* (string): One or more YAML documents (Kubernetes/OpenShift objects).
- `platform` (string): Target platform.
- `version` (null/string): Platform version, e.g. '4.22' (OCP) or '1.35'.

## insight

What is this, and what does it say?. Start here for anything the user pastes. Names what the input is (events, pod status, logs, an Alertmanager payload, a policy denial, a ticket, manifests, a Helm template, a build log, a Containerfile, an SBOM or scanner report, a packet trace, must-gather paths, a question; several at once) and runs every analyser that applies: diagnosis with reported issues and team memory, the denial explainer, the audit, the documentation. Returns every finding with its source, read-only next steps and what was not analysed and why. When the input is a QUESTION about something this product does, `answeredBy` names the command that answers it and why -- a question about exposure and node access is answered by `posture scan`, not by reading pods. It is empty whenever the input was recognised as something pasted, and empty for a sentence reporting a malfunction, because the diagnosis above it is the answer to those. Read-only, local.

- `platform` (null/string)
- `text`* (string): Anything pasted: events, describe output, logs, an Alertmanager payload, Ceph health output (ceph health detail or ceph status, text or JSON), a policy denial, a ticket, manifests or a Helm template, a build log, a Containerfile, an SBOM or scanner report, or a question.
- `version` (null/string)

- `text`* (string): An error message, events, logs or a symptom in words.
- `version` (null/string): The cluster's OpenShift version (4.20 or 4.20.8): keeps only issues that can affect it.

## operator_inventory

Installed OLM operators in manifests. Which OLM operators the given ClusterServiceVersions, Subscriptions, InstallPlans and OperatorGroups describe: package, version (and whether it was stated or read off the name), catalog, channel, approval mode, namespace and the namespaces it serves (copies OLM writes into each target namespace are folded into one operator), phase, a pending upgrade or a Manual approval waiting. A Subscription with no installed CSV, and a CSV with no Subscription, each get their own state. What the input could not show is part of the answer: with no ClusterServiceVersions the verdict is not-determined, never zero operators. Secret objects are dropped unread.

- `manifests`* (string): OLM objects as YAML: ClusterServiceVersions, Subscriptions, InstallPlans, OperatorGroups (a List, or `oc get csv,sub,ip,og -A -o yaml` output, works). Other kinds are ignored; Secret objects are dropped unread.
- `top` (integer): How many operators to return.

## operator_known_issues

Which installed operators the release notes name in a reported issue. For each OLM operator the objects describe (as operator_inventory reads them), the issues in the bundled OpenShift release notes that name its product, for the cluster's release (openshift_version): id, link, known or fixed, the OpenShift release of the fix, the release-notes source and the corpus date. Matching goes through a table of the names the notes use per package: an operator with no entry is 'no-alias', never clean, and a release outside the index is not determined. A fix is stated as an OpenShift release, so whether the installed operator carries it is always not determined. Secret objects are dropped unread.

- `issues_per_package` (integer): How many issues to return per package.
- `manifests`* (string): OLM objects as YAML, as for operator_inventory (`oc get csv,sub -A -o yaml` output works). Secret objects are dropped unread.
- `openshift_version` (null/string): The cluster's OpenShift version (4.21, 4.21.9 or 4.21.0-rc.1): only that release's notes are searched. Without it every indexed release is searched and the answer is incomplete.
- `top` (integer): How many operators to return.

## policy_generate

Turn audit rules into admission policies. Generate ValidatingAdmissionPolicy (with binding) and/or Kyverno ValidatingPolicy YAML from kube-noob's audit rules, in audit (warn and record) or enforce mode, for a platform. One policy per rule decidable from one object; each names its rule, fix and source. Rules that need other objects or that the API server already enforces are listed with the reason. Nothing is applied.

- `allow_large` (boolean): Return the rendered YAML even when it is larger than 128 KiB. Off by default: every rule on every engine renders about 380 KB (~95,000 tokens), which is more than most callers can hold, and a result a caller cannot read is worse than one that says how to narrow the request. When it is off and the set is too large, the counts and `skipped` come back as usual with `yamlOmitted: true` and the byte count, and nothing is truncated.
- `engines` (array): vap: ValidatingAdmissionPolicy + binding (built into Kubernetes 1.30+); kyverno: Kyverno ValidatingPolicy (policies.kyverno.io/v1, Kyverno 1.18+).
- `exceptions` (null/string): An exception list (YAML, kube-noob.io/v1 ExceptionList): active entries become exemptions in their rule's policy (with the ReplicaSets and pods their workloads make); expired or refused ones are listed.
- `exclude_namespaces` (array): Namespaces the policies skip, besides kube-system, kube-public and kube-node-lease.
- `mode` (string): audit warns and records; enforce refuses
- `platform` (string)
- `rules` (array): Rule ids such as KN-S001 (default: every rule).
- `version` (null/string): OpenShift (4.20) or Kubernetes (1.33)

## policy_migrate_check

Check legacy Kyverno policies for their CEL form. Kyverno 1.20 removes the kyverno.io ClusterPolicy, Policy, CleanupPolicy and legacy PolicyException. Lint them rule by rule against the policies.kyverno.io types: direct, inverted (a deny or a negated pattern: the CEL validation must state what is allowed), manual (JMESPath, API calls, anchors, strategic merge patches) or blocked (no documented CEL equivalent), each with the field path, the target kind, the reason and the Kyverno documentation section (pinned commit). Rules that map directly get a draft CEL policy and a kyverno test fixture skeleton to prove it. Nothing is applied or rewritten.

- `drafts` (boolean): Include a draft CEL policy for each rule whose fields all map directly, and a kyverno test fixture skeleton per policy (good and bad resources run against the legacy rule and the draft).
- `policies`* (string): One or more legacy Kyverno policies (YAML): kyverno.io ClusterPolicy, Policy, ClusterCleanupPolicy, CleanupPolicy or PolicyException. Other documents are listed and skipped; Secrets are not read.

## posture_report

Latest drift and policy report. The newest daily report in this install's data folder: objects added, removed and changed since the previous snapshot (with the fields that changed), findings new and fixed, and open findings by namespace, owner and rule. Local data only.

- no arguments

## posture_scan

Attack paths in manifests. Rank the paths from an exposure (Route, Ingress, LoadBalancer or NodePort Service) to what a compromised pod could do: node access (privileged, hostPath, host namespaces) or Kubernetes API rights through its ServiceAccount token (read Secrets, exec, create workloads, escalate). Score = exposure x blast radius; every step names the field that proves it, with a fix. Secret objects are dropped unread.

- `manifests`* (string): Routes, Ingresses, Services, workloads, ServiceAccounts and RBAC objects (YAML). Secret objects are dropped unread.
- `top` (integer): How many ranked paths to return.

## red_team

Red-team manifests. Hostile-auditor scenarios: node crash, zone outage, RWX split-brain, exposure, privilege escalation, upgrade blocking, secret leaks, resource starvation, supply chain.

- `manifests`* (string): One or more YAML documents (Kubernetes/OpenShift objects).
- `platform` (string): Target platform.
- `version` (null/string): Platform version, e.g. '4.22' (OCP) or '1.35'.

## rhacs_compare

Compare RHACS policies with kube-noob's rules. Map every policy in an RHACS (StackRox) export to kube-noob rules by name and criteria: overlap (same setting, with severity and scope differences), related (the same risk seen through image, runtime or API-event data), gap (a deploy-time setting kube-noob has no rule for), outside (image contents, runtime behaviour, API events, label conventions) or unexplained (criteria kube-noob does not know). Lists disagreements and the rules no policy covers. Local only.

- `outcomes` (array): Only return policies with these outcomes (default: all).
- `policies`* (string): An RHACS policy export as JSON: {"policies": [...]} from the RHACS portal (Export policy to JSON) or POST /v1/policies/export, a list of policies, or one policy.

- `apply_fixes` (boolean)
- `blueprint` (null/object): Generator blueprint (see generate_manifests).
- `manifests` (null/string): Existing manifests to review.
- `platform` (null/string)
- `request`* (string): What the user wants, in their words.
- `version` (null/string)

- `limit` (integer)
- `query`* (string)

## threat_model

## upgrade_risks

Known risks for an OpenShift update. Before updating OpenShift from one x.y.z version to another: the risks Red Hat declares for that update in the public update graph (conditional updates, as an OpenShift Update Service serves them), from a bundled snapshot, offline. Each risk has its name, message, link, the version that fixes it and a verdict: applies (declared for every cluster), check (one fact decides it, with the read-only command or must-gather file that shows it) or cannot evaluate offline (its PromQL, as written). Whether the update is in your channel is not checked.

- `arch` (null/string): The release architecture (multi for a multi-architecture payload). Without it, every architecture is checked and a risk declared for some of them only says which.
- `current`* (string): The OpenShift version the cluster runs, x.y.z, e.g. 4.20.3.
- `target`* (string): The version to update to, x.y.z, e.g. 4.21.4.

- `manifests`* (string): One or more YAML documents (Kubernetes/OpenShift objects).
- `platform` (string): Target platform.

## vuln_report

Assess scanner output: VEX, exploitation, reachability. Read Trivy or Grype JSON, CycloneDX or SPDX SBOMs, or an RHACS image scan into one finding per package, version and CVE (with the fix version); apply Red Hat VEX (a not-affected or already-fixed finding drops out, citing the statement); mark CISA KEV entries; and, with the manifests, rank by exposure, privileges and RBAC reach with each finding's attack path. SBOM packages are matched against Red Hat VEX. Local only.

- `image` (null/string): Treat every report as this image (registry/repo:tag or @sha256:...).
- `kev` (null/string): Optional: the CISA KEV catalog JSON (known_exploited_vulnerabilities.json, CC0).
- `manifests` (null/string): Optional: the YAML that runs the images; findings are then ranked by exposure and privileges and shown with their attack path.
- `products` (array): Red Hat product CPE prefixes the images belong to (default: from the RHEL release in the report, e.g. cpe:/o:redhat:enterprise_linux:9).
- `reports`* (array): Scanner output as JSON text: Trivy (trivy image -f json [--list-all-pkgs]), Grype (grype -o json), a CycloneDX or SPDX 2 JSON SBOM, or an RHACS image (GET /v1/images/{id}). Reports of the same image are assessed together.
- `top` (integer): How many ranked findings to return.
- `trust_report_vex` (boolean): Honour a CycloneDX report's own analysis (not_affected, resolved, false_positive). Off by default: the findings it marks are kept, with a note.
- `vex` (array): Optional Red Hat CSAF VEX documents (JSON) to apply on top of the local redhat-vex corpus.
